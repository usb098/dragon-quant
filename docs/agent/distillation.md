# 顶级游资心法与交割单蒸馏流程

本文定义每位交易者独立的资料处理、理念结构化、交割单验证与 Skill/Agent 接入流程。目标是蒸馏可验证的交易框架，而不是模仿人物口吻或把所有人的交易经验混成一套规则。

## 一、先按人物和资料类型隔离

给每位交易者分配稳定的 expert_id，例如 \`chen_xiaoqun\`、\`trader_b\`。每位专家的原始心法、采访、复盘和交割单独立存放。不同人物不共享原始知识库；协同层只交换规范化后的判断、证据和适用范围。

推荐的私有工作目录（已加入 Git 忽略）：

\`\`\`text
intelligence-private/
  chen_xiaoqun/
    originals/       # 原始 PDF / DOCX / XLSX / CSV，不改写
    extracted/       # 可搜索文本、表格、页码/单元格定位
    principles/      # 逐条理念与适用边界
    trades/          # 交割单事件化记录
    evaluations/     # 样本验证、反例、版本评估
  trader_b/
    ...
\`\`\`

原始资料不要提交公开 Git、不要放进 wheel，也不要默认上传到 LLM。每个文件建立 source_id、原始哈希、文件名、资料类型、交易者、记录日期/区间、页码或工作表定位、解析版本。事实、本人原话、二手转述、研究者推断必须分开标注。

## 二、心法文档：拆成原子理念

不要整篇摘要后直接写 Agent Prompt。先把每个独立主张拆成一个 principle_id，并记录：

1. **理念原文**：必要时保留短句，定位到文件/页码/段落。
2. **研究解释**：把口语化表述转成可判定语言；不得把推断伪装为原话。
3. **适用范围**：A 股/港股/期货、短线/波段、流动性、市值、市场环境。
4. **触发条件**：哪些可观察事实同时满足才适用。
5. **动作语义**：观察、等待确认、回避、减风险等；不要先写具体买卖价或仓位。
6. **失效条件**：什么变化说明理念不再适用。
7. **风险边界**：一字板无法成交、流动性、公告不确定性、监管停牌等。
8. **反例与未知**：哪些案例不符合这条理念、哪些字段缺失时必须拒绝判断。
9. **证据等级**：原始本人材料、二手资料、样本观察、研究者推断分层标注。

建议把口述经验写成结构：

\`\`\`text
IF（市场环境 + 主线状态 + 个股角色 + 量价/承接条件）
THEN（观察/确认/回避/退出的原则）
UNLESS（失效条件或风险事件）
UNKNOWN WHEN（关键字段缺失）
\`\`\`

同一段话若包含“情绪周期”“只做龙头”“分歧转一致”等多个主张，应拆开为不同 principle_id。不要把相关性写成因果关系。

## 三、交割单：还原决策事件，不只看盈亏

每笔交易至少转成一个结构化事件，字段包括：

- 交易日期、标的、买卖方向、成交时间、成交价、成交数量/金额、费用；
- 交易前的市场阶段、主线、个股角色、连板高度、流动性与可得证据；
- 交易者当时写下的入场理由、预期、退出理由、纪律偏离；
- 实际盈亏、持有时长、最大有利/不利波动、滑点与是否真实可成交；
- 原始交割单来源、页/行定位、解析置信度。

**不能只从买入记录猜测交易理由**。理由需能回溯当时的复盘/笔记/采访；如果没有，标记 unknown。不要把事后解释当作事前决策依据。

验证时按“决策质量”和“交易结果”分开：
- 决策质量：入场时证据是否符合已蒸馏原则、是否遵守前提和失效条件。
- 交易结果：扣费用/滑点后的实际收益、回撤、尾部损失、成交可得性。
- 统计口径：样本数量、年份/行情阶段、标的覆盖、持有周期、资金规模、成交限制和幸存者偏差。
- 对照组：在相同市场阶段、相似流动性与角色下，与不符合该原则的样本比较。
- 反例：必须保留失败交易、止损交易、未成交委托和错过机会，避免只分析成功案例。

## 四、理念验证：先证据，再写规则

将每条 principle 形成正例、反例、边界例。验证步骤：

1. 按时间排序，冻结每个交易日当时可见的信息。
2. 训练/归纳期与验证期按时间切分，绝不随机打乱时间序列。
3. 用 walk-forward（滚动向前）验证；计算佣金、印花税、过户费、滑点、涨跌停无法成交、停牌等约束。
4. 按行情阶段分层报告样本数、遵守率、收益分布、最大回撤、尾部损失和无法评估比例。
5. 做消融测试：去掉该理念后表现是否仍存在；防止多个理念重复描述同一市场变量。
6. 规则版本化。修改理念条件时创建新版本，不能覆盖旧结果。
7. 未通过样本验证的理念只作为定性研究材料，不进入自动排序或交易决策。

## 五、什么时候建 Skill，什么时候建 Agent

- **Skill**：稳定的理念说明、术语词典、判断清单、输入要求、标准输出格式、反例与来源索引。
- **Deterministic Expert Adapter**：能从量化字段明确判断的阈值/条件/状态机；可单元测试、可回测。
- **LLM Research Agent**：非结构化公告、产业链、政策、新闻、访谈语义和证据冲突；必须引用来源、标时间、保留不确定性。不能替代确定性数据计算。
- **协同 Coordinator**：先比对 market_scope、time_horizon、交易风格和数据覆盖，再决定互补、反方质询或一致性检查；不可比时分组展示，不投票。

每位专家独立维护 \`SKILL.md\`、\`principles.yaml\`、Adapter、评估样本和版本。协调器不得覆盖专家原始输出，也不得将单专家意见称为共识。

## 六、首次资料交付建议

先选择**一位交易者 + 1–3 份代表性心法 + 1 份交割单解析样本**做试点，不要一次性把所有人物和所有文件混在一起。先校准解析字段、来源定位和理念拆分质量，再批量处理。

用户把资料上传到当前对话后，可以按文件类型处理 PDF/DOCX/XLSX/CSV：提取文本/表格、保留页码或工作表定位、整理理念条目、解析交易事件、找正反例，并产出可审阅的 Expert Skill 草案。未经单独同意，不把原始文件发送给外部 LLM；线上 Agent 只接收已保存的结构化摘要。
